# 后台巡检补充：入口保护与功能去留

## 背景

用户确认后台也需要一起巡检，希望未来后台操作更丝滑，并找出没有用的功能，说明为什么没有用、未来是否可能用到、是否需要删除。

## 本次补充处理

### 1. 后台页面入口保护

原状态：

- 后台页面主要依赖 `app/admin/layout.tsx` 在浏览器端请求 `/api/admin/me`。
- 未登录访问后台页面时，页面壳可能先返回，再跳转登录页。
- 后台 API 本身已有服务端权限校验，未登录会返回 `401`，但页面体验不够干净。

已处理：

- 在 `proxy.ts` 中增加后台页面快速拦截。
- 未登录访问 `/admin` 或 `/admin/*` 时，直接跳转 `/admin/login`。
- 登录页 `/admin/login` 不拦截。
- 跳转时保留 `next` 参数，后续可以继续做“登录后回到原页面”。

注意：

- 这里仅做轻量入口保护，只检查 `admin_session` Cookie 是否存在。
- 真正的 JWT、账号是否禁用、角色权限仍由 `/api/admin/*` 的服务端校验负责。
- 没有把数据库查询放进 Proxy，避免影响全站请求速度。

### 2. 清理后台批量导入接口无用函数

- 删除 `app/api/admin/products/bulk-import/route.ts` 中未使用的 `numberOrDefault`。
- 不改变产品批量导入行为。

## 功能去留判断

### 明确保留并持续优化

- 仪表盘：后台入口，保留。
- 产品管理、血清产品：核心业务，保留。
- 首页广告位、自媒体内容：市场运营入口，保留。
- 产品文档、产品图片：产品说明书和标曲图上传入口，保留。
- 说明书生成：产品资料生产工具，保留。
- 每日知识生成、知识候选审核：AI 客服学习闭环，保留。
- 积分商城、兑换订单、购买积分审核、用户管理：会员和积分体系核心，保留。
- 文献引用审核：积分奖励和文献展示核心，保留。
- 代理商管理、联系我们相关配置：渠道信息核心，保留。
- 运维中心：备份、健康检查、存储清理入口，保留给超级管理员。
- 管理员管理、系统设置：权限和配置入口，保留。

### 保留兼容，不作为独立功能运营

- `/admin/papers`
- `/admin/reviews`

原因：

- 当前只是旧路径跳转到 `/admin/citations`。
- 删除会导致旧链接失效。
- 代码简单，维护成本低。

### 暂时归档隐藏，不建议直接删除

- `/admin/pages`
- `/admin/pages/[id]/editor`
- `/api/admin/pages`
- `/api/admin/pages/seed`

原因：

- 当前侧边栏没有入口，不属于日常后台主流程。
- 属于早期页面 CMS/可视化编辑器，与现在“首页广告位、自媒体内容、系统设置”的运营方式重复。
- 部分页面仍直接使用前端 Supabase anon client，不符合现在统一后台 API 权限体系。
- 代码质量问题最多，是后台 lint 错误的主要来源。

未来是否会用：

- 如果以后要做“可视化装修首页/内页”的能力，可以重构后复用概念。
- 但不建议在当前状态重新开放给管理员使用。

建议：

- 现阶段继续隐藏，不直接删除。
- 后续如果 1-2 个月没有明确可视化装修需求，可将页面和 API 移入归档目录，或删除并保留数据库备份。

## 后续建议

- 后台列表页继续分页化：文献审核、用户管理、产品文档批次。
- 把 `/admin/pages` 作为一个单独的小项目处理：要么重构成统一权限的 CMS，要么彻底归档。
- 全站 lint 仍有历史错误，主要是早期 `any` 类型、React hooks 新规则、早期页面编辑器代码；不影响当前构建，但建议分模块清理。
