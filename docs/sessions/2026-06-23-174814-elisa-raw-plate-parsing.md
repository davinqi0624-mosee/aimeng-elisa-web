# ELISA 原始孔板数据解析修复

## 背景

用户把 `Human LRP1.xlsx` 中的 OD 原始孔板数据粘贴到 `/lab/analysis` 后，网站生成的标准曲线与 Excel 报告中的曲线不一致。截图显示网站把 `0.0482、0.1782、0.2522...` 这些 OD 值误当成了 X 轴浓度，因此曲线几乎变成水平线，R² 也异常接近 0。

## 原因

`Human LRP1.xlsx` 的原始数据页包含多段 A-H 行：

- 布局图：A-H 对应浓度/样本编号。
- OD 原始数据：A-H 第一列是标准品 OD，第二列以后是样本 OD。
- 结果浓度表：A-H 是计算后的浓度结果。

旧解析逻辑无法区分这些区域，在用户只粘贴 OD 原始孔板表时，容易把 OD 值当成浓度参与 4PL 拟合。

## 修改内容

- 修改 `app/lab/analysis/page.tsx`
  - 增加 ELISACalc 原始孔板表识别。
  - 遇到 A-H 行且第一列 OD 单调上升时，自动映射为默认 8 点标准曲线：
    `0、125、250、500、1000、2000、4000、8000 pg/mL`。
  - 第一列作为标准品 OD，后续列作为未知样本 OD。
  - 对 OCR 误识别的宽表做兜底：如果表头写成“浓度(pg/mL) 标准品OD值”，但第一列其实是 8 个递增 OD 值，则自动把第一列改作标准品 OD，并补齐默认标准浓度。
  - 增加安全拦截：如果标准品浓度最大值小于 10 且 OD 都在 0-4 范围，提示用户可能把 OD 当成浓度，避免生成错误曲线。
  - 标准品结果表增加“反算浓度”和“回收率”，保留“预测 OD / 残差”用于判断标准曲线拟合质量。
  - 样本结果增加“孔位”列，并按 96 孔板孔位/样本列排序，例如 `A02-H02` 后再显示 `A03-H03`，避免样本 1#、2# 交叉显示。

- 修改 `app/api/lab/analysis/ocr/route.ts`
  - 强化 OCR 提示词：A-H 原始孔板截图中第一列若是标准品 OD，不要把这些 OD 当成浓度，应按 A-H 映射为默认标准浓度。

## 验证

- `npm run build` 通过。
- 用 `Human LRP1.xlsx` 原始数据页验证，标准点识别为：
  - `0 -> 0.0482`
  - `125 -> 0.1782`
  - `250 -> 0.2522`
  - `500 -> 0.3778`
  - `1000 -> 0.6057`
  - `2000 -> 0.9186`
  - `4000 -> 1.4691`
  - `8000 -> 2.216`
- `node scripts/verify-elisa-4pl.mjs` 通过，R² 约为 `0.9998715`。
- 用用户截图中的 OCR 错列文本验证，系统可自动修正为默认标准浓度，不再弹出“第一列像 OD 值”的错误。
- 样本排序验证通过：按 `A02、H02、A03、E03...` 等孔位顺序排序，而不是按识别顺序交叉显示。
