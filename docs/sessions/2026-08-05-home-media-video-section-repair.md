# 2026-08-05 首页视频段修复

## 问题

首页自媒体/视频窗口无法直接播放，右侧内容也容易显示无效的后台记录。

经检查：

- `home_media_items` 数据库中共有 4 条记录。
- `product-assets/home-media` Storage 目录只有 6 个封面图片。
- 全部 Storage bucket 中没有真实视频文件对象。
- 当前有效内容只有一条剪映外链：`一个视频让你速通ELISA实验`。
- 另外几条“本地视频”记录的 `external_url` 为 `assdfasd` 或 `/videos`，不是可播放视频地址。

## 修复

- `lib/home-media.ts`
  - 收紧本地视频判断逻辑。
  - “本地视频”必须是 `.mp4/.webm/.ogg/.m4v/.mov` 等真实视频文件地址，才进入前台播放。

- `app/api/home-media/route.ts`
  - 增加实时读取配置，避免旧缓存。
  - 前台接口过滤无效视频记录，防止占位地址干扰首页。

- `app/page.tsx`
  - 首页右侧目录改为可交互。
  - 本地视频点击后在左侧窗口直接播放。
  - 外链内容点击后跳转到对应平台。
  - 无效视频不再抢占播放窗口。

- `app/videos/page.tsx`
  - 使用 no-store 读取最新后台内容。

- `app/admin/home-media/page.tsx`
  - 上传本地视频后只回填视频地址，不再立即强制保存整条记录。
  - 管理员确认标题、分类、封面后点击保存，流程更清楚。

- `next.config.ts`
  - 将上传代理限制从 50MB 调整到 120MB，与后台视频 100MB 限制保持一致。

## 验证

- `npm run build` 通过。
- `SKIP_BUILD=true npm run deploy:aliyun` 部署成功。
- 线上 `npm run health` 通过。
- `GET http://106.14.215.238/api/home-media` 返回 HTTP 200。
- 当前前台接口只返回 1 条有效内容，符合 Storage 中没有本地视频文件的事实。

## 后续操作

重新上传本地视频时，请在后台 `自媒体内容`：

1. 填写标题、分类、摘要。
2. 点击“上传本地视频”。
3. 看到“视频已上传成功，请确认标题、分类和封面后点击保存。”
4. 点击“保存自媒体内容”。
5. 回到首页或 `/videos` 检查播放。

## 2026-08-05 追加修复

用户反馈后台上传后首页仍不显示，后台列表仍显示“视频地址无效”。

再次核查：

- `home_media_items` 中 4 条记录仍然没有真实视频地址。
- 全部 Supabase Storage bucket 中 `videoCount = 0`，说明本地视频文件没有真正落到 Storage。
- 后台文案写着“上传后自动保存”，但代码实际只回填表单状态，未自动保存到数据库，容易造成“我已经上传了，但首页读不到”的误解。

已追加修复：

- 后台点击“上传本地视频”后，如果正在编辑已有内容，或新内容已填写标题，会自动把视频 URL 保存到 `home_media_items`。
- 保存成功后提示“视频已上传并保存成功，首页会直接播放。”
- 如果新建内容还没有标题，只上传文件并提示补全标题后保存。
- 已重新构建并部署线上，健康检查通过。

当前旧记录仍是历史无效地址，需要重新编辑对应内容并上传一次真实 MP4/WebM/MOV 文件。
