# 管理员“用户管理”权限修复

日期：2026-08-27

## 问题现象

- 超级管理员给普通管理员王青增加了“用户管理”权限。
- 管理员权限表中已经显示该权限，但王青刷新后台后仍看不到“用户管理”菜单。

## 根因

- 后台侧边栏把 `/admin/users` 写死为仅 `super` 角色可见，没有读取 `user_manage` 权限。
- 用户管理 API 同样只允许超级管理员，导致即使只补菜单，普通管理员仍然无法读取用户数据。
- 管理员认证对象没有统一携带数据库中的实时权限，菜单和接口权限判断容易产生差异。

## 修复内容

- 管理员会话验证时，从 `admin_permissions` 实时读取有效权限。
- `/api/admin/me` 返回实时权限并禁用响应缓存，权限变更后刷新后台即可生效，无需退出重登。
- 普通管理员拥有 `user_manage` 时显示“用户管理”菜单。
- `/api/admin/users` 改为校验 `user_manage`：
  - 超级管理员始终允许。
  - 普通管理员必须拥有 `user_manage`。
  - 无权限管理员即使直接输入接口或页面地址，也无法读取用户数据。

## 数据与线上验证

- 数据库确认王青账号 `Qing-W`：角色为 `admin`、状态正常、`user_manage=true`。
- 王青 `/api/admin/me`：HTTP 200，返回 `user_manage`。
- 王青 `/api/admin/users?limit=1`：HTTP 200。
- 无 `user_manage` 权限管理员访问同一接口：HTTP 403。
- ESLint：通过。
- Next.js 生产构建：通过。
- 阿里云部署：成功。
- 线上健康检查：23 个页面和 4 个公共 API 全部通过。

## 使用说明

超级管理员以后勾选或取消“用户管理”权限后，对方刷新后台页面即可看到最新结果。
